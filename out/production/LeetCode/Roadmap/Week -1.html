📘 Big-O Notation — what it means and how to read it

Big-O tells you how the running time and memory of your code grow as the input gets bigger. It's not a stopwatch — it's a shape. O(1) means the time never grows, no matter the input size (like grabbing arr[0]). O(n) means time grows in a straight line with input (one loop over n items). O(n²) means time grows as a square (a loop inside a loop). O(log n) means time barely grows even for huge input (binary search — cutting the problem in half each step). You read it off your own code: count the loops, see if they're nested, see if the work inside a loop depends on n again.

✏️ Tiny warm-up problems (revise these fast later)

1. What's the time complexity of this loop? 
for (int i = 0; i < n; i++) {
    System.out.println(i);
}
Reveal answer
O(n) — one loop, runs n times, O(1) work each time.
2. What's the time complexity of this one? 
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        System.out.println(i + j);
    }
}
Reveal answer
O(n²) — a loop inside a loop, both going up to n.
3. What's the time complexity of this one? 
int i = n;
while (i > 1) {
    i = i / 2;
}
Reveal answer
O(log n) — i gets cut in half every step, so it only takes about log₂(n) steps to shrink to 1.

Concept

📘 Concept needed: HashMap in Java

A HashMap<K, V> stores data as key → value pairs. Think of it like a real dictionary: you look up a word (the key) and instantly get its meaning (the value) — you don't have to read every page from the start. Internally, Java uses a technique called hashing: it runs the key through a formula (a "hash function") that converts it into a number, and uses that number to jump almost directly to the right storage slot. That's why get() and put() are O(1) on average — no scanning required, unlike an ArrayList where finding something means checking element after element (O(n)).

The methods you'll use constantly:
• map.put(key, value) — insert or update a value for a key.
• map.get(key) — retrieve the value for a key (returns null if the key isn't there).
• map.containsKey(key) — check if a key exists (returns true/false, doesn't touch the value).
• map.getOrDefault(key, defaultValue) — get the value, or a fallback if the key is missing.

Clarification questions

✏️ Quick check — can you answer these before moving on?

You want to store that "apple" costs 40. What's the correct line of code using a HashMap called prices?
Reveal answer
prices.put("apple", 40); — put() always takes (key, value) in that order.
If prices does NOT contain the key "banana", what does prices.get("banana") return?
Reveal answer
null — not an error, not 0, just null. This is why containsKey() is often checked first if null could be confused with a real value.
If you call prices.put("apple", 55) when "apple" already maps to 40, what happens?
Reveal answer
The old value is overwritten — "apple" now maps to 55. A HashMap key is always unique; putting again just updates it.
LeetCode problem
Two Sum Easy
Ask: Given an array of numbers and a target, return the indices of two numbers that add up to the target.

Now that you understand HashMap in Java, try writing this yourself in Java before opening the hints below.

💡 Reveal approach — step by step (hints)

Approach

  1. Brute force: check every pair with two nested loops → O(n²). That's your baseline, but it's slow.
  2. Better idea: as you walk through the array once, ask 'have I already seen the number that completes this pair?' — that's target - nums[i].
  3. Use a HashMap<Integer,Integer> to store (value → index) of numbers you've already visited.
  4. At each index i: compute complement = target - nums[i]. If map.containsKey(complement), you found your pair — return {map.get(complement), i}.
  5. Otherwise, put nums[i] and its index into the map, and move on.

Complexity

Time O(n) — one pass. Space O(n) — the map can hold up to n entries.
Reveal full Java solution 
import java.util.HashMap;

public int[] twoSum(int[] nums, int target) {
    HashMap<Integer, Integer> seen = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        if (seen.containsKey(complement)) {
            return new int[] { seen.get(complement), i };
        }
        seen.put(nums[i], i);
    }
    return new int[] {}; // no answer found
}
💡 This is THE classic HashMap problem — the pattern 'store what I've seen, look up the complement' shows up constantly.

📘 Concept needed: HashSet in Java

A HashSet<T> is like a HashMap that only cares about keys — there's no value attached. It stores a collection of items where every item is guaranteed unique: trying to add something that's already in the set silently does nothing. It uses the exact same hashing trick as HashMap internally, so checking "is this already in my set?" is O(1) average, instead of O(n) if you used a plain array or ArrayList and scanned through it by hand.

The methods you'll use constantly:
• set.add(value) — add an item (does nothing if it's already there).
• set.contains(value) — check if an item exists (true/false).
• set.remove(value) — remove an item if present.
• set.size() — how many unique items are currently stored.

Clarification questions

✏️ Quick check — can you answer these before moving on?

You call set.add("cat") twice in a row. What is set.size() afterward?
Reveal answer
1 — a HashSet silently ignores the second add() because "cat" is already there. No error, no duplicate.
What's the time complexity of set.contains(x), and why is that faster than checking an ArrayList for the same thing?
Reveal answer
O(1) average — hashing jumps straight to where x would be stored. An ArrayList's contains() is O(n) because it has to check elements one by one until it finds a match or reaches the end.
How would you remove all duplicates from an existing ArrayList in one line, using a HashSet?
Reveal answer
Set<Integer> unique = new HashSet<>(myList); — passing the list into the HashSet constructor keeps only unique values automatically.
LeetCode problem
Contains Duplicate Easy
Ask: Given an array, return true if any value appears at least twice.

Now that you understand HashSet in Java, try writing this yourself in Java before opening the hints below.

💡 Reveal approach — step by step (hints)

Approach

  1. Brute force: compare every pair → O(n²). Skip that.
  2. A HashSet only stores unique values and gives O(1) add/lookup.
  3. Walk through the array. For each number, check if it's already in the set.
  4. If yes → duplicate found, return true immediately.
  5. If no → add it to the set and continue. If you finish the loop with no matches, return false.

Complexity

Time O(n). Space O(n) worst case (all unique, set holds everything).
Reveal full Java solution 
import java.util.HashSet;

public boolean containsDuplicate(int[] nums) {
    HashSet<Integer> seen = new HashSet<>();
    for (int num : nums) {
        if (seen.contains(num)) return true;
        seen.add(num);
    }
    return false;
}
💡 Alternate one-liner: new HashSet<>(list).size() != list.size() — but write the loop version first so you understand the O(n) walk-through.

📘 Concept needed: The 'running tracker' pattern (single-pass technique)

No HashMap or HashSet needed here — this problem is about a different, equally important pattern: walking through an array once while keeping a running variable updated as you go (like a "best value so far" tracker). Instead of comparing every pair of days (which would be O(n²)), you make one pass and, at each step, only need to remember two things: the lowest price you've seen so far, and the best profit you've found so far. This "keep a running best/min/max as I scan" idea is one of the most common building blocks in array problems — you'll see it again and again.

Two small Java things worth knowing for this pattern:
• Integer.MAX_VALUE — the largest possible int value, a handy starting point when you want "anything I see will be smaller than this."
• A single for loop that updates 1–2 variables as it goes is usually all you need — no nested loops, no extra data structure.

Clarification questions

✏️ Quick check — can you answer these before moving on?

If you initialize int minPrice = Integer.MAX_VALUE; before a loop, why does that make sense for tracking a running minimum?
Reveal answer
Because the very first real price you see is guaranteed to be smaller than Integer.MAX_VALUE, so it will immediately replace it as the new minimum — you don't need a special 'first iteration' check.
In one pass over an array, can you track BOTH a running minimum and a running maximum profit at the same time?
Reveal answer
Yes — that's exactly what this problem does. You update minPrice whenever you see a new low, and separately update maxProfit whenever (currentPrice - minPrice) beats your best profit so far. Both updates happen inside the same single loop.
LeetCode problem
Best Time to Buy and Sell Stock Easy
Ask: Given daily stock prices, find the maximum profit from buying on one day and selling on a later day.

Now that you understand The 'running tracker' pattern (single-pass technique), try writing this yourself in Java before opening the hints below.

💡 Reveal approach — step by step (hints)

Approach

  1. Brute force: try every pair of buy-day/sell-day → O(n²). Too slow for large inputs.
  2. One-pass idea: as you scan left to right, keep track of the lowest price seen so far — that's your best possible buy day up to this point.
  3. At each day, ask: 'if I sold today, having bought at the lowest price so far, what's my profit?' Compare that to your best profit found so far.
  4. Update minPrice whenever you see a new lower price. Update maxProfit whenever today's profit beats the current best.

Complexity

Time O(n) — one pass. Space O(1) — just two variables.
Reveal full Java solution 
public int maxProfit(int[] prices) {
    int minPrice = Integer.MAX_VALUE;
    int maxProfit = 0;
    for (int price : prices) {
        if (price < minPrice) {
            minPrice = price;
        } else if (price - minPrice > maxProfit) {
            maxProfit = price - minPrice;
        }
    }
    return maxProfit;
}
💡 This 'track the running minimum while scanning' trick reappears everywhere — remember the shape, not just this problem.
